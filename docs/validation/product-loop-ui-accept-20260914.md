# Product Loop UI Accept Validation

Date: 2026-09-14

## Scope

This validation covers the real Windows desktop UI decision path after a
pending Handoff exists:

```text
Project Overview
  -> Review Handoff
  -> Preview what will change
  -> Confirm Decision
  -> Project Overview
```

The Handoff was created by `ProductLoopUiSeed` through `AppServices`. The seed
does not write `AcceptedProjectState`; it only establishes governance, creates
an Attempt, and records a pending Handoff.

## Result

The desktop UI showed:

```text
Handoffs to review: 1
Godot counter change prepared for review.
The score button now adds 2 per click.
Godot headless validation passed.
Awaiting Authority decision
```

After the UI Confirm action, the desktop UI showed:

```text
1 accepted statement(s).
No handoffs are awaiting review.
The score button now adds 2 per click.
Authority accepted Worker result
```

## Restart Result

The Workbench process was force-stopped and started again with the same
project and isolated database. The new process showed:

```text
Recovered from Project World
1 accepted statement(s).
No handoffs are awaiting review.
The score button now adds 2 per click.
```

## Boundary

Certified:

- Real desktop Project Overview loaded the pending Handoff.
- Real desktop Review Handoff page loaded the proposed contribution.
- Real desktop Preview action showed the Authority effects.
- Real desktop Confirm Decision committed the Authority decision.
- Accepted Project State and Summary became visible in Overview.
- A forced process restart recovered the accepted state.

Not certified by this record:

- Provider-generated Completion Package in the desktop UI.
- A three-round `+1 -> +2 -> +3` desktop walkthrough.
- New Leader session text generated by a live provider after restart.

The provider-independent Acceptance Spine and the live Codex/Godot service gate
remain covered by their existing certification records.
